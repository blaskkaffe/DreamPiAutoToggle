# The web service and page

Read before touching `netswitch_web.py`, `netswitch_probes.py` or `page/`. Back to [CLAUDE.md](../CLAUDE.md).

## Page files and behaviour

- The page is three plain files in `page/` (`index.html`, `page.css`, `page.js`); `netswitch_web.build_page()` joins them at startup into one document (`@@CSS@@`/`@@JS@@` markers in index.html) kept in memory as `PAGE_BYTES`, so the browser still makes one request. No Python-string escaping: write JS exactly as it runs. `install.sh` copies `page/`. Check with `sh tests/run.sh` (it runs `node --check` on the JS and verifies every `$("id")` exists).
- The web page works on Python 3 and 2.7. It serves a static page that polls `GET /api` (JSON) every 1 s; buttons POST via XMLHttpRequest (plain form POST + 303 still works without JS). A background thread checks internet every 30 s. The debug panel is hidden behind a "Debug log" toggle button, and that button itself only shows when "Debug log" is ticked under Network in the settings (per browser, `localStorage` key `netswitch-debug`); the log is only polled while it is open. The selected-network box (`#net`, class `now rows`) also holds the status: closed it shows the network name and, centred underneath, the DreamPi status dot and text (the DreamPi label hidden); clicking it adds class `open`, which shows the DreamPi label and the Modem, Internet and Pi rows. `render()` keeps `open` when it updates the network class. Rows keep their first line on one line (`.nw`, ellipsis if too long) with a smaller second line (`.sub.blk`: modem "3 min ago", Pi uptime + IP). With the Dreamcast background the box turns translucent grey with its network-coloured border, like the Dreamcast BIOS pop-ups (the user wants it that way). The debug log (`#log`) never wraps (`white-space:pre`): one entry per row, long ones scroll sideways. A cogwheel opens a full-screen settings overlay (`#settings`) holding the Default network switch, Auto reset, the phone-number table, Appearance and the Status LED settings (`#led-section`, shown only when the LED count is above 0, see docs/led.md). The settings sections (`.sec`: Network, Phone numbers, Appearance, `#gpio-section`, `#led-section`, About) sit in `.cols` (`column-width:420px`, `break-inside:avoid`), and `#settings .in` is widened by media queries (920 / 1340 / 1780 px, one step per extra column), so wide screens get 2-4 columns and phones keep the single 460px column; the header spans all columns. The effect/level pop-ups are positioned inside `#led-section` and keep working in a column.
- Page styling: colours are CSS variables in `:root` (`--dcnow`, `--dcnet` and lighter `-l` variants). One corner radius `--r` (29px) for all big boxes and buttons. Main buttons are `.pill` (network colour with a 5px lighter border); the status box, selected-network box, warnings and the full-width `.wide` Debug log button share that shape, small buttons `.pill-s`, settings groups `.card` with `.srow` rows, and every checkbox (Auto reset, Dreamcast background, Follow) uses the one `.cbox` style. Buttons and the Default network switch are slightly translucent (rgba) so the optional background shows through. The cogwheel and close icons are inline SVGs in `#3a3a3a`. In the LED table, the colour swatch, effect chip and level chip are all 30px tall; tabs pick the network; `#fx-pop` and `#lvl-pop` (class `.pop`) are the pop-up menus. The status dot previews the effect with CSS animations (`DOT_FX`).
- Dreamcast background (optional, off by default, per browser via `localStorage` key `netswitch-bg`): `static/dc-background.js` is Robert Dale Smith's `background.js` from RobertDaleSmith/vmu-icon-maker (MIT), wrapped as `window.DCBackground.start(el)/stop()`, without his performance toggle and clock, pausing on `visibilitychange`. `static/three.min.js` is Three.js r128 from the same repo. The page loads both lazily when the switch is on and adds `dcbg` to html and body. His blue gradient is painted on the fixed `#dcbg` layer itself (100lvh, translateZ), not with `background-attachment: fixed`, which iOS Safari ignores; the script sizes the canvas from that container and ignores small height-only resizes (mobile toolbars). Tab icons: `static/favicon-dcnow.png` / `favicon-dcnet.png` (64 px, transparent) and `touch-*.png` (180 px on #111, apple-touch-icon), made from images the user supplied (DreamPi logo cropped above its text; the purple Flycast logo); the page swaps `#fav`/`#touch` when the selected network changes. `GET /static/<name>` serves only the files listed in `STATIC_FILES` (cached a day); `install.sh` copies `static/`. Credits and licences: README "Credits" and `static/LICENSES.txt` (the user wants credit in the README, not on the page).

## Service robustness, HTTPS

- HTTPS: `install.sh` makes a self-signed certificate (`https.crt`/`https.key` in `/opt/dreampi-netswitch`, SAN `dreampi.local`, `<hostname>.local`, the Pi's IPv4 addresses; 820 days because Apple rejects > 825; renewed by the installer when < 30 days are left) with `openssl req -config` (no `-addext`, for older OpenSSL). The web service is started as `netswitch_web.py <http port> <https port>` (443 by default, `0` = off, `--https-port=N` / `--no-https`). The HTTPS server runs in a second thread; the TLS handshake happens in each request's thread (`finish_request`), so a browser sitting on the certificate warning can't block the accept loop. If the certificate is missing or the port is taken, HTTP keeps working. Both servers are threading (`ThreadingMixIn`).
- Web service robustness: listens dual-stack (`::` with IPV6_V6ONLY off, falls back to IPv4) because phones often try the IPv6 address of dreampi.local first; `request_queue_size` 64; `Handler.timeout` 20 s; every request runs through `_safely()` (500 + traceback in the journal instead of a dropped connection); `watchdog()` GETs `/ping` every 20 s and exits after 3 failures so systemd restarts it (`Restart=always`, `RestartSec=3`, `StartLimitIntervalSec=0`, Nice=-5). The page and static files are kept in memory with their gzip; the page's own POSTs send `X-Requested-With` and get 204 instead of a 303 + full page. `wifi-powersave-off.sh` runs as `ExecStartPre` and switches Wi-Fi power saving off (it resets on reboot).

## Measurements and actions

- Modem identification (`netswitch_probes.py`) is **passive only**: nothing is ever sent to the modem, and DreamPi is never stopped or restarted. `modem_port()` reads that port file; `_usb_info(port)` is a pure sysfs read (`/sys/class/tty/<tty>/device`, walked up to the `idVendor`/`idProduct`/`manufacturer`/`product`/`serial` files), never touches the modem, and is how `modem_plugged()` (the port path exists) and the make/model label come from. `modem_compat(usb)` matches the USB descriptor's manufacturer+product string against `KNOWN_MODEMS`/`UNKNOWN_MODEMS` (only "descriptor contains the known name", never the other way round, or a short bad entry like `conceptronic c56u` would match the longer good `conceptronic c56u-v2` as a substring); the list and its source (a DreamPi modem-compatibility forum thread) are comments above `KNOWN_MODEMS`, expected to grow. `api_state()`'s `modem.plugged`/`label`/`compat` and a "not detected" / "known not to work" warning box come from the same functions; `about()` adds a Modem row with the label and compatibility note. An earlier version also actively probed the modem over the serial port (`ATI`/`AT+GM*`) to show its firmware, stopping and restarting `dreampi.service` around it; on real hardware that left DreamPi stuck re-opening the serial port ("Opening modem on ..." never clearing) instead of completing, so it was removed - see git history (`probe_modem`/`run_modem_check`/`start_modem_check`, removed) before reviving anything like it, and test against real hardware first.
- Hang up (`POST /hangup`, button at the bottom of the open network box, tap twice; the row `#hang-row` only shows, and the server only acts, while `dreampi_state()` starts with `call`): `force_hangup()` in a thread ends the call the way DreamPi does: `pkill -TERM -x pppd` (dreampi.py's CONNECTED loop waits for pppd's "Exit" in /var/log/messages, then sends +++ ATH0 and restarts the dial tone) and `pkill -TERM -f dcnet.rpi` (netlink's `dcnet_connect()` polls for it, then reconnects the modem and starts the dial tone). If `dreampi_state()` isn't `ok` within 30 s, or nothing was running, it runs `systemctl restart dreampi.service`. Progress in `/api` `hangup`, the debug log and the journal. No DreamPi files are touched.
- Pi health (`pi_health()`, sampled every 2 s in `checker()`): CPU % from /proc/stat deltas, RAM from /proc/meminfo (MemAvailable), temperature from thermal_zone0, uptime, and the firmware's throttled flags (`/sys/devices/platform/soc/soc:firmware/get_throttled`, else `vcgencmd get_throttled`, at most every 10 s; bit 0 under-voltage now, 1 capped, 2 throttled, 16/18 since boot). State bad = under-voltage/throttled now or >= 80 °C (LED message `pi`, warning box), warn = since boot or >= 70 °C. `/api` gives `line1` (CPU, RAM, temp; kept on one line), `line2` (uptime, LAN IP from `lan_ip()`: the source address of a UDP socket "connected" to 192.0.2.1, no packet sent) and `warn`. Shown as the Pi row, `pi=` in /status, `pi_problem` in the net state file.
- Versions (`about()`, `GET /about`, About card in settings): DreamPi's scripts carry `#dreampi.py_version=YYYYMMDDhhmm` / `#netlink_version=...` lines that its updater compares; there is no image version file. The add-on version is written to `/opt/dreampi-netswitch/version` by install.sh (git date + short hash of the checkout).
- Network detection (web service, `checker()`): `link_state()` every 2 s reads `/sys/class/net` (Ethernet = eth*/en* with carrier, Wi-Fi = wireless iface up) and `/proc/net/route` (default route, not via ppp/tun/lo, = "network"); `internet_checker()` runs in its own thread (30 s while OK, 5 s while failing, immediately when links change). Both go to `/tmp/dreampi-netswitch.net` (JSON, atomic), which the LED service reads via `network_state()` (ignored when older than 20 s). No network / no internet also add a warning box on the page.
