# The web service and page

Read before touching `netswitch_web.py`, `netswitch_probes.py` or `page/`. Back to [CLAUDE.md](../CLAUDE.md).

## Page files and behaviour

Phone numbers (the **numbers module**, `modules/numbers/`, layout `picker` widget over `GET`/`POST /numbers`): the reply is the standard picker answer (`netswitch_numbers._reply()`: groups = the four actions with their numbers, `defaults`, `rules`: min / max length, how many per action, allowed characters `0-9*#`, unique across actions, the texts); the page saves the whole table with `POST /numbers` (server cleans and dedupes, `netswitch_numbers.clean_numbers()`); each group has an Add button that opens one shared pop-up (moved into the card, closed by Enter, Escape, a click elsewhere or closing Settings); the short instruction and Restore default numbers sit at the bottom. The hook picks changes up on the next call, no restart.

- The page is a frame plus the layouts of the enabled **modules**: `page/index.html` (header, cog, `#warnings`, `#dash`, the Settings overlay with `#set-boxes`, `#bg`), `page.css`, `page.js` (kit, hooks, `/api` loop), `widgets.js` (the layout engine, the standard widgets, the module picker) and `boot.js`, plus each enabled module's `page.css` / `page.js` (see [modules.md](modules.md)). `netswitch_web.build_page()` joins them into one document (`@@CSS@@`/`@@JS@@` markers; `window.LAYOUT` = the merged `layout.json`s and the palette) kept in memory as `PAGE_BYTES`, so the browser still makes one request; `refresh_page()` rebuilds it when a page file or a module was added, removed, switched, moved or edited (checked on every request). No Python-string escaping: write JS exactly as it runs. `install.sh` copies `page/` and `modules/`. Check with `sh tests/run.sh` (it runs `node --check` on the JS, with all modules and with none, and verifies every `$("id")` exists) and `sh tests/ui/run.sh` (Chromium). Unknown GET/POST paths answer 404.
- The web page works on Python 3 and 2.7. It serves a page that polls `GET /api` (JSON) every 1 s and redraws only what changed (`setText` / `setHtml`: no flicker, little work on a phone); buttons POST via XMLHttpRequest (the page needs JavaScript: it is drawn from the layout). A background thread checks internet every 30 s. The selected-network box (the switcher module's `infobox` widget, class `now rows`) holds the status: closed it shows the network name and, centred underneath, the DreamPi status dot and text; tapping it adds class `open`, which shows the labels and the Modem, Internet and Pi rows (and Hang up while a call runs). Rows keep their first line on one line (`.nw`, ellipsis if too long) with a smaller second line (`.sub.blk`: modem "3 min ago", Pi uptime + IP). The debug log (`console` widget with `nowrap`) never wraps: one entry per row, long ones scroll sideways; it is only polled while its bar is open. A cogwheel opens a full-screen settings overlay (`#settings`); its boxes (`.sec`) sit in `.cols` (`column-width:420px`, `break-inside:avoid`), and `#settings .in` is widened by media queries (920 / 1340 / 1780 px, one step per extra column), so wide screens get 2-4 columns and phones keep the single 460px column; the header spans all columns. Pop-ups are positioned inside their card and keep working in a column.
- Page styling (the shared building blocks are the "page kit", see [modules.md](modules.md)): colours are CSS variables: the global palette of 16 colours (`--c-<id>`, `-l` lighter variants, `-rgb` triples; `core.colours_css()` is put before `page.css`) and `--primary` / `--primary-l` / `-rgb`, which a `.c-<id>` class on an element (a module's box, or `body` for the page) points at one palette colour; `/api` `colours` and `primary` update them live. Never write a colour as hex in CSS or JS, name a palette id in the module's manifest or layout. One corner radius `--r` (29px) for all big boxes and buttons. Main buttons are `.pill` (primary colour with a 5px lighter border); the status box (`.now`), warnings and the full-width `.wide` Debug log button share that shape, small buttons `.pill-s`, settings groups `.card` with `.srow` rows, and every checkbox (the module switches, Follow) uses the one `.cbox` style. Buttons are slightly translucent (rgba) so the optional background shows through. The cogwheel and close icons are inline SVGs in `#3a3a3a`. The LED module's table, chips and pop-up menus are styled in `modules/led/page.css` (see [led.md](led.md)). The status dot previews the effect with CSS animations (`DOT_FX`).
- Dreamcast background (the **background module**, `modules/background/`, off by default; on = the background is shown in every browser, there is no per-browser switch): `dc-background.js` is Robert Dale Smith's `background.js` from RobertDaleSmith/vmu-icon-maker (MIT), wrapped as `window.DCBackground.start(el)/stop()`, without his performance toggle and clock, pausing on `visibilitychange`. `three.min.js` is Three.js r128 from the same repo. The module's `netswitch_background.py` serves its three files (`/background/three.min.js`, `/background/dc-background.js`, `/background/LICENSES.txt`, cached a day); its layout is `{"background": {"type": "fullscreen"}}` and its `page.js` registers `background("background", fn)`, which the page calls with a host element in `#bg` (class `keep-visible`, which the base's rule hiding the page behind Settings skips); it creates the `#dcbg` layer in it and loads both scripts lazily, adds `dcbg` to html and body, and removes it again if they can't be loaded; the grey translucent boxes on top of it are `body.dcbg ...` rules in the module's `page.css`. His blue gradient is painted on the fixed `#dcbg` layer itself (100lvh, translateZ), not with `background-attachment: fixed`, which iOS Safari ignores; the script sizes the canvas from that container and ignores small height-only resizes (mobile toolbars). Tab icons: `static/favicon-dcnow.png` / `favicon-dcnet.png` (64 px, transparent) and `touch-*.png` (180 px on #111, apple-touch-icon), made from images the user supplied (DreamPi logo cropped above its text; the purple Flycast logo); the switcher module's `page.js` swaps `#fav`/`#touch` when the selected network changes. `GET /static/<name>` serves only the files listed in `STATIC_FILES` (the tab icons, cached a day); `install.sh` copies `static/`. Credits and licences: README "Credits" and `modules/background/LICENSES.txt` (the user wants credit in the README, not on the page).

## Optional modules

Everything the page shows is a module in `modules/`, loaded by `netswitch_modules.py` and (except the always-on ones) switched and ordered in Settings > System > Modules. How they plug in (manifest, layout, widgets, colours, web entry, hooks, installer, tests) is in [modules.md](modules.md).

## Online-players module (`modules/players/`)

A module like the others (see [modules.md](modules.md)): its `netswitch_players.py` registers `GET /players`, its `layout.json` draws the box (an `infobox` with a carousel, a compact list, a status line and links, bound to the ready-made `parts` / `games` / `list` / `status` fields of the reply); with the folder deleted or the module switched off `/players` answers 404 and the page has none of it. `players_sources.json` (path `core.PLAYERS_SOURCES`) lists `{name, url, network}` sources; `refresh()` fetches each (8 s timeout, 1 MB cap, http(s) only), `parse_players()` accepts several JSON shapes (list of player objects, object with a players list, games with player lists, game->players mapping) and normalises network names to `DCNow!`/`DCNET`; the cache lasts 60 s and refreshes in a background thread when `GET /players` finds it stale. The box is the standard `infobox` widget (the same box as the network one, so it looks the same and follows the Dreamcast background): closed it shows the coloured counts (`parts`, in the switcher's DCNow! / DCNET colours) and the games carousel (`games`, scrolls only when the line is wider than the row, a duplicate copy makes the loop seamless, `prefers-reduced-motion` stops it); open it shows the games, the players (`list`, max 40vh), the Status line (per-source detail and errors) and the links. All of those are computed in `netswitch_players.view()` (`games_line()` etc.), not in the page. Clicks on links and the list don't toggle the box (`.keep`). The box is always shown while the module is on (no per-browser switch); the layout's data source asks `/players` while the page is visible (every 60 s; 2 s only while the server's first load is pending: `retry_if: retry`), because the closed box shows data too. **Default sources:** `https://dc99.net/online/dcnet_status.php` and `https://dreamcast.online/now/api/users.json` (https first, plain http as fallback). `parse_sections()` reads every top-level section of the dc99 feed that holds a `players` or `users` list (so KOSnet or any new network appears without a code change): the section name picks the network (`dreampi`/`dcnow` = DCNow!, `dcnet` = DCNET, `kosnet` = KOSnet, else its own name), a section's `players` list wins over its `users` list, a section with `online: false` is skipped, entries with an `online` field must have it true. Per-source section counts go to the page's grey detail line. `parse_dcnow()` reads dreamcast.online's `users[]` (`username`/`country`/`current_game_display`/`online`, offline entries skipped). The shapes come from `ui_dcnow.c`/`dcnet_fetch` (`dcnow_fetch.c`) in the user's openMenu repo, where they were checked against live responses; **dc99.net and dreamcast.online could not be reached from the development sandbox (egress blocked), so no real response has been seen here and the KOSnet section is handled by the generic section rule, not by a known sample.** Players present in two sources are listed once (name + network); the first copy gets any missing game/country from the other.

**Favorites** (`players_favorites.json` = `core.PLAYERS_FAVORITES`, `{"games": [...], "players": [...]}`, max 30 each, cleaned by `clean_names()`): a Settings box (`favorites`) with a `picker` on `GET`/`POST /players/favorites`. The reply is the picker answer plus, per group, `choices` (`[{value, label, sub, disabled}]`: the game list with `game_status()` words - green/online, work in progress (`sub` "work in progress"), not online (greyed out, `disabled`) - plus games being played now that the list lacks; for players the names online now), `notes` (`{name: "work in progress"}` shown behind a favorite's tag) and `free` (may a typed value be added: players yes, games no) and, for games, `initial` (the text shown when nothing is typed and no choice is `now`; the picker shows only choices with `now: true` until the user types, then all that match). The picker's choice list is generic (`choices` on any group, see modules.md). **Game lists** are `players_sources.json` entries with `"kind": "games"` (`game_sources()`, default Dreamcast Live with `urls` tried in turn; `parse_games_text()` takes JSON - `parse_games()`: a list of objects with `name`/`title` + a `status`/`colour`/`online` field, an object holding such a list, or `{"Game": "status"}` - or the HTML table of dreamcastlive.net, `parse_games_html()`: name = first cell with text, status = the `online-icon` / `wip-icon-v2` / `offline-icon` image in the row, format seen from a copy the user pasted; **which page of the site holds the table is an unverified guess**, the host is blocked from the development sandbox). The list is re-read every 6 h (30 min while only the bundled `games_snapshot.json` is known, which is the fallback so the picker is never empty). After each refresh (and each save) `write_watch()` writes `core.PLAYERS_WATCH` (`/tmp/dreampi-netswitch.players`: `{"time", "games", "friends"}` = the favorites that are online, matched by `same_game()` / case-insensitive name); the LED module reads it through `core.players_watch()` (ignored when older than 5 minutes) for the messages `players-game` and `players-friend`. The module's `start()` runs a background loop that refreshes every 60 s while there are favorites, so the LEDs work with no page open.

## Tag for openMenu, reboot

`GET /tag` is the tiny status code for openMenu over the PPP link (see `docs/openmenu.md`). `POST /reboot` (the **Reboot and Update module**, `modules/rebootupdate/`: the Reboot card below the System card; PIN-protected) reboots the whole Pi via its `start_reboot()` (`sleep 2; systemctl reboot`, detached so the answer gets out); the page confirms first (extra warning while `dreampi_state` starts with `call`) and then polls `/ping` until the Pi answers again and reloads.

## Updates (`modules/rebootupdate/netswitch_update.py`, Settings > System; part of the Reboot and Update module)

`GET /update` returns the cached check (never starts a check by itself: updates are only looked for when the user presses Check now; "Not checked yet" until then), `POST /update/check` forces one, `POST /update/start` updates. Both POSTs need the `X-Requested-With` header (the page's own requests): the update runs git and the installer as root, and a bare cross-site form post must not be able to start it. **Add-on check:** `install.sh` records `version_commit` (full hash), `src_dir` (the checkout) and `install_ports`; the repo/branch come from the checkout's `origin` URL and current branch (default `blaskkaffe/DreamPiAutoToggle`, `main`); the GitHub API gives the branch head and `compare/<local>...<head>` says ahead (update available), behind (this install is ahead of GitHub), diverged or unknown commit (local changes). **DreamPi check:** the `#<file>_version=` line of `dreampi.py`/`netlink.py`/`dcnow.py` on the Pi vs `raw.githubusercontent.com/Kazade/dreampi/master/` (what DreamPi's own updater follows); newer remote = message + the note that DreamPi updates itself at start with internet unless `/boot/noautoupdates.txt` exists. **Update now** (only with a recorded git checkout): `update_script()` (validated values only, runs as root) does `git fetch origin <branch>` + `merge --ff-only FETCH_HEAD` as the checkout's owner (`runuser`) and then `sh install.sh <http port> --https-port=<n>` from the remembered ports; it is started with `systemd-run` (else `setsid`) so the installer's restart of this service doesn't kill it. Status `running`/`ok`/`failed` in `/tmp/dreampi-netswitch.update` (a finished result is only reported for 10 min), output in `.update.log`. In Settings > System the update controls are the last rows of the System card (`#upd-row` Updates/Check, the DreamPi note, `#upd-do-row` Update now, then `#upd-log`); `_log_tail()` returns the last 14 non-empty lines with colour codes, progress-bar rewrites (`\r`) and control characters removed and each line cut at 300 characters, and `renderUpdLog()` shows them as a small scrolling console (`.updlog`, monospace, wraps long lines inside the card, errors red, success green, follows the end while you are not scrolled up). The page polls through the restart and reloads on `ok`. Not verified on a Pi: the `systemd-run`/`runuser` path.

## Security (`netswitch_security.py`)

The web service runs as root. Checks done in `netswitch_web.py` before an action: `security.host_allowed()` on every request (Host must be an IP, `localhost`, a single-label or private-suffix name, the Pi's own host name, or a line in `allowed_hosts` (`core.ALLOWED_HOSTS`); a missing Host header from an HTTP/1.0 client such as the Dreamcast passes; otherwise 421) against DNS rebinding; `security.post_allowed()` on every POST (`Origin`, else `Referer`, must name the request's own Host; the page's `X-Requested-With` header passes; with neither header nor Origin, or with a strict action, 403; only a same-site form post without the header is accepted, and never for the paths a module lists as `PROTECTED`: `/reboot` and `/update/start` from the Reboot and Update module, `/wificonnect` from the Wi-Fi module); for those, `security.check_pin()` with the `X-Netswitch-Pin` header when `core.ADMIN_PIN` exists (PBKDF2-SHA256 salted hash, mode 600, written only by `install.sh --pin` via `netswitch_security.py set`, 401 wrong/missing, 429 for 60 s after 5 wrong tries, a damaged file refuses everything). `GET /api` has `pin` (the page prompts once and keeps the PIN in memory only); Settings > System shows a PIN row. Responses carry `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'`, `nosniff`, `Referrer-Policy: same-origin`. `_body(limit)` clamps Content-Length (a negative one used to read until the timeout); `/wificonnect` cuts SSID to 32 and password to 63 characters. **Update:** `origin_problem()` requires the checkout's `remote.origin.url` to match `ORIGIN_RE` (GitHub https/ssh) and equal `update_origin` (written by `install.sh` from the checkout; absent on older installs = accepted once, then recorded); the script fetches that exact URL (`U`) with `GIT_ALLOW_PROTOCOL=https:ssh` instead of the name `origin`, the branch may not start with `-` or contain `..`, the start is under a lock, and the status file/log are removed and recreated with `set -C`/`O_NOFOLLOW` so a planted symlink in `/tmp` isn't followed. `install.sh` writes the unit with `NoNewPrivileges=yes`, `ProtectSystem=full`, `ProtectControlGroups=yes`, `ProtectKernelModules=yes`, keeps `/opt/dreampi-netswitch` at mode 755 and `netswitch_wifi_setup.save_network()` writes `wpa_supplicant.conf` with mode 600. Tests: `tests/test_security.py`. **Not verified on a Pi:** the systemd sandbox directives (a unit that no longer starts would show in `journalctl -u dreampi-netswitch`), `--pin` prompting on a real terminal, and `systemd-run`/`runuser` with the pinned-URL fetch. Known gap: the other state files in `/tmp` still have predictable names.

## Service robustness, HTTPS

- HTTPS: `install.sh` makes a self-signed certificate (`https.crt`/`https.key` in `/opt/dreampi-netswitch`, SAN `dreampi.local`, `<hostname>.local`, the Pi's IPv4 addresses; 820 days because Apple rejects > 825; renewed by the installer when < 30 days are left) with `openssl req -config` (no `-addext`, for older OpenSSL). The web service is started as `netswitch_web.py <http port> <https port>` (443 by default, `0` = off, `--https-port=N` / `--no-https`). The HTTPS server runs in a second thread; the TLS handshake happens in each request's thread (`finish_request`), so a browser sitting on the certificate warning can't block the accept loop. If the certificate is missing or the port is taken, HTTP keeps working. Both servers are threading (`ThreadingMixIn`).
- Web service robustness: listens dual-stack (`::` with IPV6_V6ONLY off, falls back to IPv4) because phones often try the IPv6 address of dreampi.local first; `request_queue_size` 64; `Handler.timeout` 20 s; every request runs through `_safely()` (500 + traceback in the journal instead of a dropped connection); `watchdog()` GETs `/ping` every 20 s and exits after 3 failures so systemd restarts it (`Restart=always`, `RestartSec=3`, `StartLimitIntervalSec=0`, Nice=-5). The page and static files are kept in memory with their gzip; the page's own POSTs send `X-Requested-With` and get 204 instead of a 303 + full page. `wifi-powersave-off.sh` runs as `ExecStartPre` and switches Wi-Fi power saving off (it resets on reboot).

## Measurements and actions

- Modem identification (`netswitch_probes.py`) is **passive only**: nothing is ever sent to the modem, and DreamPi is never stopped or restarted. `modem_port()` reads that port file; `_usb_info(port)` is a pure sysfs read (`/sys/class/tty/<tty>/device`, walked up to the `idVendor`/`idProduct`/`manufacturer`/`product`/`serial` files), never touches the modem, and is how `modem_plugged()` (the port path exists) and the make/model label come from. `modem_compat(usb)` matches the USB descriptor's manufacturer+product string against `KNOWN_MODEMS`/`UNKNOWN_MODEMS` (only "descriptor contains the known name", never the other way round, or a short bad entry like `conceptronic c56u` would match the longer good `conceptronic c56u-v2` as a substring); the list and its source (a DreamPi modem-compatibility forum thread, plus the user's own `Conexant USB Modem`, confirmed on a real Pi) are comments above `KNOWN_MODEMS`, expected to grow. `api_state()`'s `modem.plugged`/`label`/`compat` and a "not detected" / "known not to work" warning box come from the same functions; `about()` adds a Modem row with the label and compatibility note. An earlier version also actively probed the modem over the serial port (`ATI`/`AT+GM*`) to show its firmware, stopping and restarting `dreampi.service` around it; on real hardware that left DreamPi stuck re-opening the serial port ("Opening modem on ..." never clearing) instead of completing, so it was removed - see git history (`probe_modem`/`run_modem_check`/`start_modem_check`, removed) before reviving anything like it, and test against real hardware first.
- Hang up (`POST /hangup`, button at the bottom of the open network box, tap twice; the action only shows (`hangup.visible`), and the server only acts, while `dreampi_state()` starts with `call`): `force_hangup()` in a thread ends the call the way DreamPi does: `pkill -TERM -x pppd` (dreampi.py's CONNECTED loop waits for pppd's "Exit" in /var/log/messages, then sends +++ ATH0 and restarts the dial tone) and `pkill -TERM -f dcnet.rpi` (netlink's `dcnet_connect()` polls for it, then reconnects the modem and starts the dial tone). If `dreampi_state()` isn't `ok` within 30 s, or nothing was running, it runs `systemctl restart dreampi.service`. Progress in `/api` `hangup`, the debug log and the journal. No DreamPi files are touched.
- Pi health (`pi_health()`, sampled every 2 s in `checker()`): CPU % from /proc/stat deltas, RAM from /proc/meminfo (MemAvailable), temperature from thermal_zone0, uptime, and the firmware's throttled flags (`/sys/devices/platform/soc/soc:firmware/get_throttled`, else `vcgencmd get_throttled`, at most every 10 s; bit 0 under-voltage now, 1 capped, 2 throttled, 16/18 since boot). State bad = under-voltage/throttled now or >= 80 °C (LED message `pi`, warning box), warn = since boot or >= 70 °C. `/api` gives `line1` (CPU, RAM, temp; kept on one line), `line2` (uptime, LAN IP from `lan_ip()`: the source address of a UDP socket "connected" to 192.0.2.1, no packet sent) and `warn`. Shown as the Pi row, `pi=` in /status, `pi_problem` in the net state file.
- Versions (`about()`, `GET /about`, About box in settings): DreamPi's scripts carry `#dreampi.py_version=YYYYMMDDhhmm` / `#netlink_version=...` lines that its updater compares; there is no image version file. The add-on version is written to `/opt/dreampi-netswitch/version` by install.sh (git date + short hash of the checkout).
- Network detection (web service, `checker()`): `link_state()` every 2 s reads `/sys/class/net` (Ethernet = eth*/en* with carrier, Wi-Fi = wireless iface up) and `/proc/net/route` (default route, not via ppp/tun/lo, = "network"); `internet_checker()` runs in its own thread (30 s while OK, 5 s while failing, immediately when links change). Both go to `/tmp/dreampi-netswitch.net` (JSON, atomic), which the LED service reads via `network_state()` (ignored when older than 20 s). No network / no internet also add a warning box on the page.
