# What is verified on real hardware

Check this before saying something works. Anything not listed under Verified has only been tried in simulation or unit tests. Update it whenever the user reports a hardware result. Back to [CLAUDE.md](../CLAUDE.md).

## Verified on hardware

Nothing on real hardware yet in this version of the add-on (the check-in board, the contacts and the kiosk script are new). Run-as-user was tried in a container (not a real systemd machine): the web service started as an unprivileged user against a root-owned code folder and a user-owned state folder served HTTP and HTTPS, read the PIN hash, imported a CSV and could not write the code folder, and `install.sh` / `uninstall.sh` ran through (stub `systemctl`, real `useradd` / `userdel`, files and ownership checked). The base it grew out of (the module system, the page kit, the update and reboot controls, the clock) ran on a small computer in an earlier add-on, but the page has been rebuilt since and none of it has been re-checked here.

## Not yet verified

- **The check-in board** (`modules/checkin/`, the `roster` widget): tested off-hardware in Chromium against the demo server (`sh tests/ui/run.sh`: at four widths, tapping, the status menu, a second browser page following the first within about two seconds, the buildings filter, the settings, the CSV import) and by unit tests. **Not seen on a computer, on a touch screen, on a TV or with more than two browser windows at once.** How it looks and feels on the real screens (button size, the 1 s refresh) is unconfirmed.
- **Several screens on one host:** only two Chromium pages against one demo server were tried. Whether a computer 3 / Zero serves 10+ screens polling `/api` once a second is untested; the answer carries the whole board (a few kilobytes per hundred people).
- **Network-booted kiosk screens** (`pxe/`, [pxe.md](pxe.md)): never run. The generated dnsmasq config, the whitelist (allow / block / pending / open mode, the image gate by address), the boot menu / assignment logic, the boot server over HTTP, the admin tool, the kiosk session's address handling and the per-screen layout are unit-tested; the image build, the boot on BIOS / UEFI hardware, whether iPXE's `prompt` / `choose` keys behave as written (I, N, S, 1-9), the serial number iPXE reads, Firefox in kiosk mode, the local-install wizard (partitioning, GRUB on BIOS and UEFI) and the root shell are not.
- **Offline bundle and restart on crash** (`offline/`, [offline.md](offline.md)): the package closure, download and install from the local repository were run for one small package on Ubuntu 24.04 with internet. Not run: the full list, a Debian 12 bundle, the Ubuntu snaps, an install on a computer with no internet at all, the kiosk browsers actually restarting after a crash, a kernel-panic reboot and the watchdog reboot (the settings are written and tested as files only).
- **Text size / colour, button sounds, theme by time, calendar, date and time, the new keyboard and emoji, the Snow background** (this look and these inputs): driven in Chromium against the demo server (`tests/ui/functional.js`, screenshots), the WebGL snow in headless Chromium with a software GL only (not on a real GPU or a kiosk screen; speed on a weak computer is unknown, the 2D fallback and the amount setting are for that), the sun's height by formula checks. Not heard: the button sounds (the page fetches and decodes them; the speakers were never tried). A tall 1080 x 1920 screen with two columns was tested at 20, 40, 60 and 80 people in Chromium only (not on a real portrait display). Not tried on a touch screen or in Firefox.
- **The Settings menus** (Layout, Text, Colours, Background; the System box in its new order; subtitles from what is chosen): driven in Chromium against the demo server (`tests/ui/look.js`, `functional.js`, `screen.js`, `palette.js`, `imagebg.js`); not on a touch screen.
- **Kiosk mode** (`kiosk/kiosk-browser.sh`, the autostart file): never run. It is adapted from CheckinChicken's script, which is the reference.
- **Contacts import** from a real CSV exported by Excel or Google Sheets (encodings, delimiters): comma, semicolon and tab and a BOM are handled and tested with made-up files only.
- **The module system** (`modules/<name>/`, Settings > System > Modules, `base/base_modules.py`, the module picker with drag and drop: mouse and keyboard tested in Chromium, touch dragging with touch events in a phone-sized Chromium context, **not on a real iPhone / Safari**): tested off-hardware.
- **Web-service safety** (Host / Origin checks, the optional PIN, update origin pinning, the systemd sandbox directives on `checkin-board.service`): tested off-hardware (`tests/test_security.py`, the PIN prompt flow driven in a browser). **Run as a user, not root** (the `checkin` user, `/opt/checkin-board` root-owned, `/var/lib/checkin-board` the service's, `CAP_NET_BIND_SERVICE`, the polkit rule and the root-owned `checkin-board-update@` / `checkin-board-reboot` units: [web.md](web.md), Who runs it): only the file permission side was run (above). **Not run on a computer with real systemd and polkit: whether the unit with its sandbox directives starts, whether it binds port 80 / 443 with the ambient capability, whether the polkit rule lets the service start the three units (and on Ubuntu 22.04, whose polkit is too old for the rule, the page's Reboot / Update do not work and the installer says so), whether a USB stick mounted for the desktop user is visible to the page, and the updater (`update-run.sh`) with a real GitHub origin.** Also not run: and `install.sh --pin` on a real terminal. See [web.md](web.md#security-netswitch_securitypy).
- **Update check and Update now:** the GitHub comparison is tested against fake responses and the update script against a local git origin with a stub installer; the real GitHub API calls and the start of the root updater through systemd (`systemctl start checkin-board-update@git.service`, then `runuser` for the git commands) have not run on a computer. The default repository is `blaskkaffe/CheckinChicken`, branch `main`: the page offers whatever the installed checkout's origin and branch say.
- **Reboot:** the endpoint is tested; the reboot itself (the root-owned `checkin-board-reboot.service`, which runs `systemctl reboot` after 2 s, started by the web service through polkit) has not been run on a computer.
