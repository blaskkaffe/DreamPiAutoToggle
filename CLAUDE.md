# Notes for Claude Code

## Goal and hard rules
- A check-in board for any Linux computer that any number of screens show in step: a row per person (in a box per department) from a CSV, grey while out, in the colour of the person's department / building while in, a status with its own colour. This repository is `blaskkaffe/CheckinChicken` (Python 3, no dependencies; the work was done on a branch `checkin2.0` of the repository `DreamPiAutoToggle`, whose history is not kept; the earlier Node.js version of CheckinChicken is gone from this repository, its ideas were ported: sticky statuses, delete a person, per-status default times, the number pad, the instant INNE / UTE switch, a title per screen). Work on `main`.
- **No Dreamcast / DreamPi / DCNow! / DCNET / modem / GPIO / LED code or wording** belongs here any more. The internals have neutral names: the service `checkin-board` and its folders (`/opt/checkin-board` the code, `/var/lib/checkin-board` the state, `/run/checkin-board*`, all set in `project.json`), `base/base_*.py` for the framework and `<module>_web.py` for a module's Python.
- **The web service is never root** (`docs/web.md`, Who runs it): user `checkin` (`project.json` `run_user`, `install.sh --user=`), code and what only the installer writes in `core.INSTALL_DIR` (root-owned, read-only for the service), everything the service writes in `core.BASE_DIR`, ports 80 / 443 by `CAP_NET_BIND_SERVICE`, reboot and update by starting three root-owned systemd units that a polkit rule names (`modules/rebootupdate/install.sh`, `update-run.sh`). **Never put a file the service must not change into `BASE_DIR`, and never let a root script read a path or value the service wrote** (`tests/test_runuser.py`, `tests/test_security.py` guard this). Not verified on a real systemd + polkit machine: `docs/hardware-status.md`.
- Python 3 only. Behaviour-changing work: run `sh tests/run.sh` before committing and add a test for a fixed bug. Keep README.md and the matching `docs/` file accurate in the same commit, including whether something is **verified on hardware** (see `docs/hardware-status.md`; never claim hardware behaviour that was only simulated).

## Structure: a small base and modules (everything shown is a module)
Details and the rules for adding or changing a module: `docs/modules.md`. The base scans `modules/`, owns the theme (global palette of 15 colours, editable in Appearance with the base widget `palette`: `core.palette_*`, routes in `base/base_web.py`, state files `palette.json` and `palette_custom.json`; the page kit) and the areas Dashboard / Settings, and draws each module's `layout.json` with standard widgets; a module needs no HTML, and no JS unless a custom widget or hook.
- **Base** (`base/`: `base_*.py`, `layout.json` and `base/page/`, copied with `project.json` to `/opt/checkin-board`; **a framework that knows no project**, `tests/test_base_neutral.py` fails when a project word gets into `base/`; the project names itself only in `project.json`: page title, data folder, tmp prefix, service, host name, icons): `base/base_core.py` = the paths from `project.json`, the palette (`colours()`, `module_colours()`), the module state (`module_manifest()`, `module_enabled()`, `module_names()` = picker order ...), `module_announcements(key)`, `service(name)`, the screen settings and the saved tile places, `log()`; no server, imported by everyone. `base/layout.json` = the base's own Settings boxes (Appearance: palette editor, columns / stretch / scale / fit / rearrange / no scrolling / hide the top bar, theme, PIN; Global colours). `base/base_modules.py` = the module loader for the web service (manifests, `layout.json` check and merge, routes, `api` hooks, `refresh()`). `base/base_web.py` = HTTP side (`api_state()` = pin / warnings / colours + the modules' `api` hooks, `GET`/`POST /modules`, `/modules/order`, `/colour`, `/colours`, HTTPS, watchdog, page assembly). `base/base_security.py` = Host/Origin checks, the optional PIN and its lock-out. `base/base_tz.py` = time zone offsets with summer time and `CITIES`. The page: `base/page/index.html` (only the frame), `page.css`, `page.js` (kit, hooks, `/api` loop), `widgets.js` (layout engine, the standard widgets incl. **`roster`**, module picker), `boot.js`.
- **Modules** (`modules/<name>/`: `module.json`, `layout.json`, its Python web entry, optional `page.js` (custom widgets only) / `page.css` (themes only) / `install.sh` / `remove.sh`): `checkin` (the board: `checkin_web.py` keeps `checkin.json`, puts the whole board in every `/api` answer, the `roster` widget draws it), `contacts` (`contacts_web.py`: CSV import / export into `contacts.json`; a custom `contacts-import` widget), `imagebg` (a picture as the page background, default off), `system` (the About box: `system_web.py` = `about()`, `lan_ip()`; always on), `rebootupdate` (`rebootupdate_web.py`, `rebootupdate_update.py`), `snow` (a WebGL snowstorm background with a day / night cycle from `core.daylight()`, default off). **The base never imports module code and never names a module**; modules import the base by name and **never each other** (a module that needs another's state reads its state file; what several modules fill together goes through `core.module_announcements()`, `modules.collect("about_rows")` or `core.service()`). The page must work with any module deleted or switched off - including all of them (`OFF=all` in the demo server). A module never writes a colour of its own (palette ids only; `tests/test_ui_kit.py` enforces the CSS rules); a new shared widget goes into `base/page/widgets.js`, its CSS into `base/page/page.css`. **Each module defines the path constants of the files it owns** (from `core.BASE_DIR` / `core.TMP_PREFIX`: `checkin_web.CHECKIN`, `contacts_web.CONTACTS` / `PHOTOS_DIR`, `imagebg_web.IMAGEBG_*`, `rebootupdate_update.UPDATE_*` ...); the base's are in `base_core.py`; `tests/support.py` imports every module and `sandbox()` redirects all of them.
- **Sync model:** one host, any number of browser screens (kiosk mode: `kiosk/`). The host's web service holds the state; every `/api` answer carries the board with a revision; pages poll once a second. State changes go through one lock and one atomic write. Peer-to-peer sync between several hosts is not built (`docs/checkin.md`).
- **PXE kiosk screens** (`pxe/`, `docs/pxe.md`): `build-image.sh` makes a small Debian image (Xorg + Openbox + Firefox kiosk), `install-pxe.sh` serves it (proxy DHCP + TFTP + iPXE + `pxe_server.py`: whitelist of serial numbers / MAC addresses (default: only approved computers boot; the rest are listed as pending), menu / per-computer settings, registry of serial + MAC, local install wizard in the image). Opt-in, not run by `install.sh`. The page sends `X-Screen: <id>` and `base_core` then keeps that screen's `screen.json` / `tile_layout.json` in `screens/<id>/` (`core.set_screen()`).
- `install.sh` makes the service user, copies the base files, `page/` and `kiosk/` to `/opt/checkin-board` (root-owned), moves an old install's state to `/var/lib/checkin-board`, syncs `modules/*/` (a module dropped from the repo is removed through its `remove.sh`), writes the `checkin-board` systemd unit, sources each module's `install.sh`.

## State is in files (cross-process; no sockets between services)
- `/var/lib/checkin-board/` (the service's): `contacts.json` (the roster), `checkin.json` (who is in, statuses, the board's settings), `modules.json`, `module_order.json`, `colours.json`, `tints.json`, `palette.json`, `time_zone`, `photos/` (profile photos), `screen.json` (columns, stretch, scale, fit, no scrolling, theme, text size / colour, button sound), `sounds/` (button sounds, copy more in by hand), `snow.json`, `palette_custom.json` (the Colour palette module's list), `settings_pin`, `background_image` / `imagebg.json`, `allowed_hosts`, `https.crt` / `https.key`. **`/opt/checkin-board/` (root's; only the installer writes these):** the code, `version`, `version_commit` / `src_dir` / `install_ports` / `update_origin` / `update_branch` (for the update), `run_user`, `admin_pin` (PIN hash). The base's paths are constants in `base/base_core.py`, each module's in its own file.
- `/run/checkin-board/` (the service's: debug log, pokes) and `/run/checkin-board-update/` (the root updater's `state.update` / `state.update.log`, readable by all).

## Texts and languages
- **English is the text in the code; Swedish is in `lang_sv.json`** (`base/` and each `modules/<name>/`, details in `docs/web.md`, Language). Every text a person reads goes through `tr()` (page.js: `setText`, `h()`, `setHtml`, templates, ...); a text with a number or name needs a **pattern** in the dictionary. Add the Swedish text in the same commit as an English one; `tests/test_i18n.py` checks the layouts. Dates are Swedish in both languages (`åååå-mm-dd`, `tt:mm`). The tests run in English (`sandbox()` writes the language file); `LANG_UI=sv` for the demo server.

## Testing without a screen
`sh tests/run.sh` runs the off-hardware tests (`tests/`: the check-in board and the CSV import with two clients in step, web config + HTTP round trips on a random port with all paths redirected into a temp dir, page JS syntax and id references, layering, shell syntax, the module system with every module removed / switched off alone and all gone, security, update, time zones). `tests/support.py` has `sandbox()` for redirecting paths. To look at the page run `python3 tests/ui/demo_server.py` (the real web service on a sandbox with the 25 people of `tests/ui/people.csv`; env switches `IN=n IMGBG=1 FAKEUPDATE=1 EMPTY=1 PEOPLE=file.csv OFF=snow|all PORT=n`, see its docstring) and screenshot it with Playwright (Chromium is pre-installed; scripts need `NODE_PATH=/opt/node22/lib/node_modules`). `sh tests/ui/run.sh` is an optional UI audit at four screen widths (overflow, clipped text, tap targets, unlabelled controls, duplicate ids, JS errors, failed requests) plus `tests/ui/functional.js`, which drives the real page; run it after changing `page/` or a layout. When editing `base/page/page.css` add rules with an exact-string anchor, never by 'first occurrence of a selector' (that once split a rule in half). Never `pkill -f demo_server` from a shell whose own command line contains that text; use `fuser -k <port>/tcp`.
