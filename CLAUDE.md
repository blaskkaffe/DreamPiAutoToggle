# Notes for Claude Code

## Goal and hard rules
- Add-on for DreamPi (Raspberry Pi bridge for the Sega Dreamcast modem) that routes calls to DC Now or DCNet.
- **Never modify DreamPi's own files** (`/home/pi/dreampi/dreampi.py`, `netlink.py`, `dcnow.py`). DreamPi auto-updates them from GitHub, and the add-on must install and uninstall cleanly without touching them.
- `netswitch_hook.py` runs inside DreamPi, which runs on **Python 2.7**. Keep it Python 2 and 3 compatible: no f-strings, no type hints, no Python-3-only stdlib. The web page runs separately under Python 3.
- Behaviour-changing work: run `sh tests/run.sh` before committing and add a test for a fixed bug. Keep README.md and the matching `docs/` file accurate in the same commit, including whether something is **verified on hardware** (see `docs/hardware-status.md`; never claim hardware behaviour that was only simulated).

## Naming in the UI
User-facing text (web page, README, log lines) spells the networks **DCNow!** and **DCNET**; the buttons read "DCNow! / DreamPi" and "DCNET / FLYCAST". Code identifiers, file names and upstream strings keep their original spelling (`dcnow`, `dcnet`, `[DCNet]` in `netlink_config.ini`, DreamPi's `DCNet Call answered` log text).

## Structure: a small base and optional modules
Details and the rules for adding or changing a module: `docs/modules.md`.
- **Base** (flat Python 3 files in the repo root, copied to `/opt/dreampi-netswitch`): `netswitch_core.py` = all path constants, state-file readers (DreamPi/modem/network/Wi-Fi), the module on/off state (`module_manifest()`, `module_enabled()` ...), debug_log(), button settings; no server, imported by everyone. `netswitch_modules.py` = the module loader for the web service (manifests, routes, `api` hooks, page parts, `refresh()`). `netswitch_web.py` = HTTP side (`api_state()`, base handlers, `GET`/`POST /modules`, HTTPS, watchdog, page assembly). `netswitch_probes.py` = what the web service measures (internet/link checks, `pi_health()`, hang up, versions, modem identification, the `checker()` loop). `netswitch_security.py` = Host/Origin checks, the optional PIN (`admin_pin`) and its lock-out. `netswitch_buttons.py` (GPIO buttons: debounce, hold, short-press functions, config reload; loads no module code) with `netswitch_gpio.py`. `netswitch_hook.py` is standalone and Python 2 compatible. The page: `page/index.html`, `page.css`, `page.js` = network box, the two buttons, GPIO (buttons) / Modules / System (Wi-Fi row at the top) + the `about_bottom` / `system_after` slots (the Reboot and Update module's rows and card), the `@@SLOT:name@@` markers and the `hook()` / `fire()` bus.
- **Modules** (`modules/<name>/`, each with `module.json`, its Python, `page.html` / `page.css` / `page.js`, optional `install.sh` / `remove.sh`; installed when the folder is there, enabled in Settings > Modules, state in `modules.json`): `numbers` (phone numbers: `netswitch_numbers.py`), `players` (online players box: `netswitch_players.py`), `wifi` (Wi-Fi setup: `netswitch_wifi_service.py` = its own `dreampi-netswitch-wifi` service, `netswitch_wifi_setup.py`, `netswitch_wifi_web.py`, default off), `led` (`netswitch_led.py` service, `netswitch_led_drivers.py` WS2812 output, `netswitch_ledconfig.py` settings / messages / `active_messages()`, `netswitch_led_web.py`; includes the LED count / pin / wire order settings), `rebootupdate` (Reboot and Update: `netswitch_rebootupdate.py` = `/reboot` and `/update/*`, `netswitch_update.py` = update check against GitHub and the page's Update now), `background` (the Dreamcast background: `netswitch_background.py` serves the module's own `three.min.js` / `dc-background.js`, default off), `debuglog` (`netswitch_debuglog.py` web side, `netswitch_hookdebug.py` runs inside DreamPi). **The base never imports module code** (one guarded exception: the hook loads `netswitch_hookdebug`; the buttons service is pure base, a hold only touches `wifi_start`/`wifi_stop`); modules import the base by name. LED and buttons code must never import `netswitch_web` (tests enforce it). The page must work with any module deleted or switched off - including all of them (`OFF=all` in the demo server). Keep a module's markup, CSS and JS in its own folder, not in the base page files, and build it from the page kit (`ui.row()`, `ui.popup()`, the kit classes and colour variables in `page.css`; see `docs/modules.md`, "The page kit"): module CSS never restyles a base class or writes `#hex` colours (`tests/test_ui_kit.py` enforces it), and a new shared widget goes into the kit. Path constants live only in core; other modules read them as `core.NAME`.
- `install.sh` copies the base files and `page/` to `/opt/dreampi-netswitch`, syncs `modules/*/` (a module dropped from the repo is removed through its `remove.sh`), writes `dreampi_netswitch.pth` into site-packages for `python`, `python2` and `python3` (the list is kept in `pth_locations`), creates and starts the `dreampi-netswitch` systemd service (web page) and `dreampi-netswitch-buttons`, sources each module's `install.sh` (the LED module adds `dreampi-netswitch-led`, the Wi-Fi module `dreampi-netswitch-wifi`; `--leds=N` (0-300) sets the starting count, `--leds=0` turns it off and hides the LED settings; the Wi-Fi module handles `--wifi` / `--no-wifi` / `--wifi-demo`, which switch the module on or off from the command line) and restarts the `dreampi` service. Older installs had flat module files and one combined `dreampi-netswitch-wifi` service (`netswitch_wifi.py`) / `wifi_button_enabled` marker: install.sh removes the old files and migrates the marker; the Wi-Fi module's install.sh rewrites that unit for its new service.

## State is in files (cross-process; no sockets between services)
- `/opt/dreampi-netswitch/`: `dcnet_mode` (exists = DCNet selected; removed on every reboot so DCNow! is selected, see `boot_id` / `core.reset_network_after_boot()`), `debug_dtmf`, `modules.json` (which modules are on), `led.json`, `numbers.json` (phone numbers, read by the hook while the numbers module is on), `led_count`/`led_gpio`, `button1_gpio`/`button2_gpio`/`button1_function`/`button2_function`/`wifi_button`, `wifi_start`/`wifi_stop`/`wifi_connect`, `version`, `version_commit`/`src_dir`/`install_ports` (for the update), `players_sources.json`, `admin_pin` (PIN hash), `allowed_hosts`, `update_origin`, `https.crt`/`https.key`. All paths are constants in `netswitch_core.py`.
- `/tmp/dreampi-netswitch.*`: `active`, `state`, `modem`, `port` (written by the hook), `net` (web service -> LED), `wifi` (Wi-Fi setup -> web/LED), `wbtest`, `update`/`update.log`; `/tmp/dreampi-netswitch-dtmf.log` is the debug timeline.
- Details of each: see the docs below.

## Testing without a Pi
`sh tests/run.sh` runs the off-hardware tests (`tests/`: buttons debounce/hold, Wi-Fi setup helpers, LED pipeline and render, web config + HTTP round trips on a random port with all paths redirected into a temp dir, page JS syntax and id references, hook Python 2 syntax guard, layering, shell syntax, the module system with every module removed / switched off alone and all gone). `tests/support.py` has `sandbox()` for redirecting paths. The routing test that needs the real `netlink.py` is described in `docs/hook.md` and is not in the suite. To look at the page run `python3 tests/ui/demo_server.py` (the real web service on a sandbox; env switches `WIFIDEMO=1 FAKEUPDATE=1 FAKEPLAYERS=1 OFF=led,wifi|all LEDS=n PORT=n`, see its docstring) and screenshot it with Playwright (Chromium is pre-installed; scripts need `NODE_PATH=/opt/node22/lib/node_modules`). `sh tests/ui/run.sh` is an optional UI audit at four screen widths (overflow, clipped text, tap targets, unlabelled controls, duplicate ids, stretched pills, JS errors, failed requests); run it after changing `page/`. When editing `page/page.css` add rules with an exact-string anchor, never by 'first occurrence of a selector' (that once split a rule in half).
