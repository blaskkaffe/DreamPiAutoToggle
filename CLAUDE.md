# Notes for Claude Code

## Goal and hard rules
- A check-in board for any Linux computer that any number of screens show in step: a row per person (in a box per department) from a CSV, grey while out, in the colour of the person's department / building while in, a status with its own colour. This branch is `checkin2.0` (the branch `development` is an old, unrelated product: **read only**, never edit it). [CheckinChicken](https://github.com/blaskkaffe/CheckinChicken) is the **reference** for features and look (read it, don't change it).
- **No Dreamcast / DreamPi / DCNow! / DCNET / modem / GPIO / LED code or wording** belongs here any more. The internals have neutral names now: the service and folder `checkin-board` (`/opt/checkin-board`, `/tmp/checkin-board.*`, set in `project.json`), `base/base_*.py` for the framework and `<module>_web.py` for a module's Python. Only the GitHub repository still has the old name (renaming it is the user's call).
- Python 3 only. Behaviour-changing work: run `sh tests/run.sh` before committing and add a test for a fixed bug. Keep README.md and the matching `docs/` file accurate in the same commit, including whether something is **verified on hardware** (see `docs/hardware-status.md`; never claim hardware behaviour that was only simulated).

## Structure: a small base and modules (everything shown is a module)
Details and the rules for adding or changing a module: `docs/modules.md`. The base scans `modules/`, owns the theme (global palette of 15 colours, editable in Appearance with the base widget `palette`: `core.palette_*`, routes in `base/base_web.py`, state files `palette.json` and `palette_custom.json`; the page kit) and the areas Dashboard / Settings, and draws each module's `layout.json` with standard widgets; a module needs no HTML, and no JS unless a custom widget or hook.
- **Base** (`base/`: `base_*.py`, `layout.json` and `base/page/`, copied with `project.json` to `/opt/checkin-board`; **a framework that knows no project**, `tests/test_base_neutral.py` fails when a project word gets into `base/`; the project names itself only in `project.json`: page title, data folder, tmp prefix, service, host name, icons): `base/base_core.py` = the paths from `project.json`, the palette (`colours()`, `module_colours()`), the module state (`module_manifest()`, `module_enabled()`, `module_names()` = picker order ...), `module_announcements(key)`, `service(name)`, the screen settings and the saved tile places, `log()`; no server, imported by everyone. `base/layout.json` = the base's own Settings boxes (Appearance: palette editor, columns / stretch / scale / fit / rearrange / no scrolling / hide the top bar, theme, PIN; Global colours). `base/base_modules.py` = the module loader for the web service (manifests, `layout.json` check and merge, routes, `api` hooks, `refresh()`). `base/base_web.py` = HTTP side (`api_state()` = pin / warnings / colours + the modules' `api` hooks, `GET`/`POST /modules`, `/modules/order`, `/colour`, `/colours`, HTTPS, watchdog, page assembly). `base/base_security.py` = Host/Origin checks, the optional PIN and its lock-out. `base/base_tz.py` = time zone offsets with summer time and `CITIES`. The page: `base/page/index.html` (only the frame), `page.css`, `page.js` (kit, hooks, `/api` loop), `widgets.js` (layout engine, the standard widgets incl. **`roster`**, module picker), `boot.js`.
- **Modules** (`modules/<name>/`: `module.json`, `layout.json`, its Python web entry, optional `page.js` (custom widgets only) / `page.css` (themes only) / `install.sh` / `remove.sh`): `checkin` (the board: `checkin_web.py` keeps `checkin.json`, puts the whole board in every `/api` answer, the `roster` widget draws it), `contacts` (`contacts_web.py`: CSV import / export into `contacts.json`; a custom `contacts-import` widget), `clock` (`clock_web.py`), `imagebg` (a picture as the page background, default off), `system` (the About box: `system_web.py` = `about()`, `lan_ip()`; always on), `rebootupdate` (`rebootupdate_web.py`, `rebootupdate_update.py`). **The base never imports module code and never names a module**; modules import the base by name and **never each other** (a module that needs another's state reads its state file; what several modules fill together goes through `core.module_announcements()`, `modules.collect("about_rows")` or `core.service()`). The page must work with any module deleted or switched off - including all of them (`OFF=all` in the demo server). A module never writes a colour of its own (palette ids only; `tests/test_ui_kit.py` enforces the CSS rules); a new shared widget goes into `base/page/widgets.js`, its CSS into `base/page/page.css`. **Each module defines the path constants of the files it owns** (from `core.BASE_DIR` / `core.TMP_PREFIX`: `checkin_web.CHECKIN`, `contacts_web.CONTACTS` / `PHOTOS_DIR`, `clock_web.CLOCK_CONFIG`, `imagebg_web.IMAGEBG_*`, `rebootupdate_update.UPDATE_*` ...); the base's are in `base_core.py`; `tests/support.py` imports every module and `sandbox()` redirects all of them.
- **Sync model:** one host, any number of browser screens (kiosk mode: `kiosk/`). The host's web service holds the state; every `/api` answer carries the board with a revision; pages poll once a second. State changes go through one lock and one atomic write. Peer-to-peer sync between several hosts is not built (`docs/checkin.md`).
- **PXE kiosk screens** (`pxe/`, `docs/pxe.md`): `build-image.sh` makes a small Debian image (Xorg + Openbox + Firefox kiosk), `install-pxe.sh` serves it (proxy DHCP + TFTP + iPXE + `pxe_server.py`: whitelist of serial numbers / MAC addresses (default: only approved computers boot; the rest are listed as pending), menu / per-computer settings, registry of serial + MAC, local install wizard in the image). Opt-in, not run by `install.sh`. The page sends `X-Screen: <id>` and `base_core` then keeps that screen's `screen.json` / `tile_layout.json` in `screens/<id>/` (`core.set_screen()`).
- `install.sh` copies the base files, `page/` and `kiosk/` to `/opt/checkin-board`, syncs `modules/*/` (a module dropped from the repo is removed through its `remove.sh`), writes the `checkin-board` systemd unit, sources each module's `install.sh`.

## State is in files (cross-process; no sockets between services)
- `/opt/checkin-board/`: `contacts.json` (the roster), `checkin.json` (who is in, statuses, the board's settings), `modules.json`, `module_order.json`, `colours.json`, `tints.json`, `palette.json`, `highlight`, `clock.json`, `time_zone`, `photos/` (profile photos), `screen.json` (columns, stretch, scale, fit, no scrolling, theme), `palette_custom.json` (the Colour palette module's list), `settings_pin`, `background_image` / `imagebg.json`, `version`, `version_commit` / `src_dir` / `install_ports` / `update_origin` (for the update), `admin_pin` (PIN hash), `allowed_hosts`, `https.crt` / `https.key`. The base's paths are constants in `base/base_core.py`, each module's in its own file.
- `/tmp/checkin-board.*`: `update` / `update.log`.

## Testing without a screen
`sh tests/run.sh` runs the off-hardware tests (`tests/`: the check-in board and the CSV import with two clients in step, web config + HTTP round trips on a random port with all paths redirected into a temp dir, page JS syntax and id references, layering, shell syntax, the module system with every module removed / switched off alone and all gone, security, update, time zones). `tests/support.py` has `sandbox()` for redirecting paths. To look at the page run `python3 tests/ui/demo_server.py` (the real web service on a sandbox with the 25 people of `tests/ui/people.csv`; env switches `IN=n IMGBG=1 FAKEUPDATE=1 CLOCK=1 EMPTY=1 OFF=clock|all PORT=n`, see its docstring) and screenshot it with Playwright (Chromium is pre-installed; scripts need `NODE_PATH=/opt/node22/lib/node_modules`). `sh tests/ui/run.sh` is an optional UI audit at four screen widths (overflow, clipped text, tap targets, unlabelled controls, duplicate ids, JS errors, failed requests) plus `tests/ui/functional.js`, which drives the real page; run it after changing `page/` or a layout. When editing `base/page/page.css` add rules with an exact-string anchor, never by 'first occurrence of a selector' (that once split a rule in half). Never `pkill -f demo_server` from a shell whose own command line contains that text; use `fuser -k <port>/tcp`.
