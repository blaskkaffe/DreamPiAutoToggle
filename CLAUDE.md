# Notes for Claude Code

## Goal and hard rules
- A check-in board for a Raspberry Pi (or any Linux host) that any number of screens show in step: a row per person (in a box per department) from a CSV, grey while out, in the colour of the person's department / building while in, a status with its own colour. It grew out of the DreamPi network switcher (branch `development`, **read only**: never edit it, it is the old product); this branch is `checkin2.0`. [CheckinChicken](https://github.com/blaskkaffe/CheckinChicken) is the **reference** for features and look (read it, don't change it).
- **No Dreamcast / DreamPi / DCNow! / DCNET / modem / GPIO / LED code or wording** belongs here any more. The old names survive only in internals that were not renamed yet: the service `dreampi-netswitch`, `/opt/dreampi-netswitch`, `/tmp/dreampi-netswitch.*`, the `netswitch_*` file names. Renaming them is a decision for the user (see Ideas for later).
- Python 3 only now (the Python 2.7 rule belonged to the DreamPi hook). Behaviour-changing work: run `sh tests/run.sh` before committing and add a test for a fixed bug. Keep README.md and the matching `docs/` file accurate in the same commit, including whether something is **verified on hardware** (see `docs/hardware-status.md`; never claim hardware behaviour that was only simulated).

## Structure: a small base and modules (everything shown is a module)
Details and the rules for adding or changing a module: `docs/modules.md`. The base scans `modules/`, owns the theme (global palette of 16 colours, the page kit) and the areas Dashboard / Settings, and draws each module's `layout.json` with standard widgets; a module needs no HTML, and no JS unless a custom widget or hook.
- **Base** (flat Python 3 files in the repo root, copied to `/opt/dreampi-netswitch`): `netswitch_core.py` = path constants, the palette (`colours()`, `module_colours()`), the module state (`module_manifest()`, `module_enabled()`, `module_names()` = picker order ...), `log()`, the Wi-Fi / update state readers; no server, imported by everyone. `netswitch_modules.py` = the module loader for the web service (manifests, `layout.json` check and merge, routes, `api` hooks, `refresh()`). `netswitch_web.py` = HTTP side (`api_state()` = pin / warnings / colours + the modules' `api` hooks, `GET`/`POST /modules`, `/modules/order`, `/colour`, `/colours`, HTTPS, watchdog, page assembly). `netswitch_probes.py` = `check_internet()`, `lan_ip()`, `about()`. `netswitch_security.py` = Host/Origin checks, the optional PIN and its lock-out. `netswitch_tz.py` = time zone offsets with summer time and `CITIES`. The page: `page/index.html` (only the frame), `page.css`, `page.js` (kit, hooks, `/api` loop), `widgets.js` (layout engine, the standard widgets incl. **`roster`**, module picker), `boot.js`.
- **Modules** (`modules/<name>/`: `module.json`, `layout.json`, its Python web entry, optional `page.js` (custom widgets only) / `page.css` (themes only) / `install.sh` / `remove.sh`): `checkin` (the board: `netswitch_checkin.py` keeps `checkin.json`, puts the whole board in every `/api` answer, the `roster` widget draws it), `contacts` (`netswitch_contacts.py`: CSV import / export into `contacts.json`; a custom `contacts-import` widget), `clock` (`netswitch_clock.py`), `imagebg` (a picture as the page background, default off), `system` (the About box, the Global colours box, Appearance: columns / stretch / rearrange / PIN: always on), `rebootupdate` (`netswitch_rebootupdate.py`, `netswitch_update.py`), `wifi` (its own `dreampi-netswitch-wifi` service, default off). **The base never imports module code**; modules import the base by name. The page must work with any module deleted or switched off - including all of them (`OFF=all` in the demo server). A module never writes a colour of its own (palette ids only; `tests/test_ui_kit.py` enforces the CSS rules); a new shared widget goes into `page/widgets.js`, its CSS into `page/page.css`. Path constants live only in core; other modules read them as `core.NAME`.
- **Sync model:** one host, any number of browser screens (kiosk mode: `kiosk/`). The host's web service holds the state; every `/api` answer carries the board with a revision; pages poll once a second. State changes go through one lock and one atomic write. Peer-to-peer sync between several hosts is not built (`docs/checkin.md`).
- `install.sh` copies the base files, `page/` and `kiosk/` to `/opt/dreampi-netswitch`, syncs `modules/*/` (a module dropped from the repo is removed through its `remove.sh`), removes what the DreamPi version left (hook `.pth` files, buttons / LED services), writes the `dreampi-netswitch` systemd unit, sources each module's `install.sh` (the Wi-Fi module handles `--wifi` / `--no-wifi` / `--wifi-demo`).

## State is in files (cross-process; no sockets between services)
- `/opt/dreampi-netswitch/`: `contacts.json` (the roster), `checkin.json` (who is in, statuses, the board's settings), `modules.json`, `module_order.json`, `colours.json`, `tints.json`, `palette.json`, `highlight`, `clock.json`, `time_zone`, `photos/` (profile photos), `screen.json` (columns, stretch, scale), `settings_pin`, `background_image` / `imagebg.json`, `wifi_start` / `wifi_stop` / `wifi_connect` / `wifi_demo`, `version`, `version_commit` / `src_dir` / `install_ports` / `update_origin` (for the update), `admin_pin` (PIN hash), `allowed_hosts`, `https.crt` / `https.key`. All paths are constants in `netswitch_core.py`.
- `/tmp/dreampi-netswitch.*`: `wifi` (Wi-Fi setup -> web), `update` / `update.log`.

## Testing without a Pi
`sh tests/run.sh` runs the off-hardware tests (`tests/`: the check-in board and the CSV import with two clients in step, web config + HTTP round trips on a random port with all paths redirected into a temp dir, page JS syntax and id references, layering, shell syntax, the module system with every module removed / switched off alone and all gone, security, update, Wi-Fi setup helpers, time zones). `tests/support.py` has `sandbox()` for redirecting paths. To look at the page run `python3 tests/ui/demo_server.py` (the real web service on a sandbox with the 25 people of `tests/ui/people.csv`; env switches `IN=n IMGBG=1 WIFIDEMO=1 FAKEUPDATE=1 CLOCK=1 EMPTY=1 OFF=wifi|all PORT=n`, see its docstring) and screenshot it with Playwright (Chromium is pre-installed; scripts need `NODE_PATH=/opt/node22/lib/node_modules`). `sh tests/ui/run.sh` is an optional UI audit at four screen widths (overflow, clipped text, tap targets, unlabelled controls, duplicate ids, JS errors, failed requests) plus `tests/ui/functional.js`, which drives the real page; run it after changing `page/` or a layout. When editing `page/page.css` add rules with an exact-string anchor, never by 'first occurrence of a selector' (that once split a rule in half). Never `pkill -f demo_server` from a shell whose own command line contains that text; use `fuser -k <port>/tcp`.

## Ideas for later
- **Ask the user:** rename the internals that still say `dreampi-netswitch` (service, `/opt/dreampi-netswitch`, `/tmp/dreampi-netswitch.*`) and the `netswitch_*` files, and the repository.
- Peer-to-peer sync between several hosts (no host at all), or a long-poll on `/checkin?since=<rev>` if one-second polling ever limits the number of screens.
- Ported from CheckinChicken so far: the board, statuses, colours, buildings, CSV. Not yet: the admin passcode screen, profile photos, per-screen titles, themes, the on-screen keyboard, the admin editors for people and statuses, "plupp" statuses.
- Move the Wi-Fi service into the module folder completely (its unit file is already written by the module's `install.sh`).
