# Notes for Claude Code

## Goal and hard rules
- Add-on for DreamPi (Raspberry Pi bridge for the Sega Dreamcast modem) that routes calls to DC Now or DCNet.
- **Never modify DreamPi's own files** (`/home/pi/dreampi/dreampi.py`, `netlink.py`, `dcnow.py`). DreamPi auto-updates them from GitHub, and the add-on must install and uninstall cleanly without touching them.
- `modules/switcher/netswitch_dreampi.py` (the hook) and every module's `hook` file (module.json) run inside DreamPi, which runs on **Python 2.7**. Keep it Python 2 and 3 compatible: no f-strings, no type hints, no Python-3-only stdlib. The web page runs separately under Python 3.
- Behaviour-changing work: run `sh tests/run.sh` before committing and add a test for a fixed bug. Keep README.md and the matching `docs/` file accurate in the same commit, including whether something is **verified on hardware** (see `docs/hardware-status.md`; never claim hardware behaviour that was only simulated).

## Naming in the UI
User-facing text (web page, README, log lines) spells the networks **DCNow!** and **DCNET**; the buttons read "DCNow! / DreamPi" and "DCNET / FLYCAST". Code identifiers, file names and upstream strings keep their original spelling (`dcnow`, `dcnet`, `[DCNet]` in `netlink_config.ini`, DreamPi's `DCNet Call answered` log text).

## Structure: a small base and modules (everything shown is a module)
Details and the rules for adding or changing a module: `docs/modules.md`. The base scans `modules/`, owns the theme (global palette of 15 colours, editable in Appearance, the page kit) and the areas Dashboard / Settings / Background, and draws each module's `layout.json` with standard widgets; a module needs no HTML, and no JS unless a custom widget, hook or background.
- **Base** (`base/`, copied to `/opt/dreampi-netswitch`; **a framework that knows no project**, `tests/test_base_neutral.py` enforces it; the project names itself only in `project.json`, its icons are in `static/`): `base_core.py` = the paths from `project.json`, the palette (screen colours only) and its editor's logic (`colours()`, `palette_*()`, `colour_tokens()`, `module_colours()`), the module state (`module_manifest()`, `module_enabled()`, `module_names()` = picker order, `module_announcements(key)` ...), `service(name)` (what a module offers the base), the theme / screen / PIN-lock settings, `time_zone()`, debug_log(), `poke()`; no server, imported by everyone. `base/layout.json` = the base's own Settings boxes (Appearance: palette editor, screen layout, theme, PIN; Global colours: Global main, the notification highlight). `base_modules.py` = the module loader for the web service (manifests, `layout.json` check and merge, routes, `api` hooks, `SERVICES`, `collect()`, `refresh()`). `base_web.py` = HTTP side (`api_state()` = pin/warnings/colours + the modules' `api` hooks, `GET`/`POST /modules`, `/modules/order`, `/colour`, `/colours`, HTTPS, watchdog, page assembly). `base_security.py` = Host/Origin checks, the optional PIN and its lock-out. `base_tz.py` = time zone offsets with summer time on any Python (zoneinfo, or its own reader of the system's tz files) and `CITIES`, the city/zone list the page offers. `base_gpio.py` = the GPIO register access that the GPIO-using modules' services share. The page: `page/index.html` (only the frame), `page.css`, `page.js` (kit, hooks, `/api` loop), `widgets.js` (layout engine, the standard widgets, module picker), `boot.js`.
- **Modules** (`modules/<name>/`: `module.json` = name / description / enabled / visible, `layout.json`, its Python web entry, optional `page.js` (custom widgets only) / `page.css` (themes only) / `install.sh` / `remove.sh`): `switcher` (network box, the two buttons, `netswitch_switcher_state.py` = its files and readers: the selected network, DreamPi's state, the button settings, `/tag`; `netswitch_switcher_hook.py` = the toggle / DCNow! / DCNET actions in DreamPi, `netswitch_dreampi.py` = the hook that wraps DreamPi's `Netlink.check_number` (its `install.sh` writes the `.pth`), `netswitch_switcher_probes.py` = what it measures (internet/link checks, `pi_health()`, hang up, modem identification, the `checker()` loop, started by its `start()`), `netswitch_switcher_buttons.py` = the GPIO buttons service `dreampi-netswitch-buttons`, the Appearance colour picks, the GPIO rows of the two physical buttons, the Modem row of About; always on), `system` (the About box: versions + GitHub; always on), `clock` (dashboard clock, `netswitch_clock.py`: large clock, world cities, the world map is the kit's `worldmap` widget, no page.js or CSS; the time zone itself is the base's `core.time_zone()`, Settings > About), `events` (DC99 events, `netswitch_events.py`: importer, SQLite store, reminders, JSON API; see docs/events.md), `players`, `openmenu` (the openMenu link: the Dreamcast's game list, Start, live info back to the Dreamcast; it announces itself with `launcher` in module.json so other modules' lists can show a Join button; `netswitch_openmenu.py`; see docs/openmenu.md), `numbers` (rows of an action + numbers, `netswitch_numbers_hook.py` = the matching inside DreamPi; the actions come from every module's module.json `actions`, done by that module's `hook` file inside DreamPi), `led` (rows of colour + the messages every module announces in its module.json `led_messages`, the order of the rows is the priority; `netswitch_led.py` service, `netswitch_led_drivers.py`, `netswitch_ledconfig.py` (also the LED value of every palette colour), `netswitch_led_inputs.py` (reads the other modules' state files), `netswitch_led_web.py`; the colour rows are the standard `triggers` widget, the calibration and colours rows the custom `led-tools`), `debuglog` (`netswitch_debuglog.py` web side, `netswitch_hookdebug.py` runs inside DreamPi), `wifi` (`netswitch_wifi_service.py` = its own `dreampi-netswitch-wifi` service, `netswitch_wifi_setup.py`, `netswitch_wifi_web.py`, default off), `rebootupdate` (`netswitch_rebootupdate.py`, `netswitch_update.py`), `background` (a background-only module: `netswitch_background.py`, default off), `imagebg` (a background with its own settings box: `netswitch_imagebg.py`, the picture of the user as the page's background, default off). Boxes with the same name in several modules are one box (best practice: shared names `system`, `about`, `gpio`, `configuration`, `appearance`, `network`; own-feature boxes named after the feature; see docs/modules.md); a module can make many boxes in both Dashboard and Settings; the picker order (Settings > System > Modules > Edit: a pop-up with drag and drop and the switches, applied on Done; `module_order.json`) is the priority; `toggle_box` in a `module.json` puts its on/off switch in a Settings box (the Dreamcast background's is in Appearance) (box order, titles, primary colour, backgrounds). **The base never imports module code and never names a module** (one guarded exception: the hook loads `netswitch_hookdebug`); modules import the base by name and **never each other**: a module that needs another's state reads its state file (format in docs/) or `/api`, and what several modules fill together goes through `core.module_announcements()`, `modules.collect()` or `core.service()` (docs/modules.md, Base and project). LED and buttons code must never import `base_web` (tests enforce it). The page must work with any module deleted or switched off (`OFF=all` in the demo server). Put what a widget shows into the module's `api()` / data answers as ready texts; to get attention a module uses the base's `highlight` (a box stands out) and `notices` (a banner) in its `api()`, never its own effect; a module never writes a colour of its own (palette ids only; `tests/test_ui_kit.py` enforces the CSS rules), and a new shared widget goes into `page/widgets.js`. **Each module defines the path constants of the files it owns** (from `core.BASE_DIR` / `core.TMP_PREFIX`); `tests/support.py` imports every module and `sandbox()` redirects them all.
- `install.sh` copies the base files and `page/` to `/opt/dreampi-netswitch`, syncs `modules/*/` (a module dropped from the repo is removed through its `remove.sh`), creates and starts the `dreampi-netswitch` systemd service (web page), sources each module's `install.sh` (the switcher module writes `dreampi_netswitch.pth` into site-packages for `python`, `python2` and `python3`, the list is kept in `pth_locations`, and adds `dreampi-netswitch-buttons`; the LED module adds `dreampi-netswitch-led`, the Wi-Fi module `dreampi-netswitch-wifi`; `--leds=N` (0-300) sets the starting count, `--leds=0` turns it off and hides the LED settings; the Wi-Fi module handles `--wifi` / `--no-wifi` / `--wifi-demo`, which switch the module on or off from the command line) and restarts the `dreampi` service. Older installs had flat module files and one combined `dreampi-netswitch-wifi` service (`netswitch_wifi.py`) / `wifi_button_enabled` marker: install.sh removes the old files and migrates the marker; the Wi-Fi module's install.sh rewrites that unit for its new service.

## State is in files (cross-process; no sockets between services)
- `/opt/dreampi-netswitch/`: `dcnet_mode` (exists = DCNet selected; removed on every reboot so DCNow! is selected, see `boot_id` / `netswitch_switcher_state.reset_network_after_boot()`), `debug_dtmf`, `modules.json` (which modules are on), `module_order.json` (picker order), `colours.json` (each module's colour picks), `tints.json` (coloured or neutral background per colour), `palette.json` (palette colours the user changed on screen), `led_colours.json` (how the LED shows a palette colour, the LED module's; the checker's `net` file also carries `dcnet_problem` / `dcnet_code` for the LED and openMenu), `palette_custom.json` (the colour palette editor's list: order, deleted, names, own colours), `led.json`, `numbers.json` (phone numbers, read by the hook while the numbers module is on), `clock.json` (the clock module's format, time zone, .beat and world time switches, cities), `highlight` (the look of the notification highlight), `screen.json` (max columns, stretch, scale, fit, drag, theme dark / light / auto), `background_image` / `imagebg.json` (the Background image module's picture and fit / darken), `settings_pin` (exists = Settings is locked with the PIN), `events.json` / `events.db` / `event_reminders.json` (the events module's settings, store and the reminders the LEDs read), `led_count`/`led_gpio`, `button1_gpio`/`button2_gpio`/`button1_function`/`button2_function`/`wifi_button`, `wifi_start`/`wifi_stop`/`wifi_connect`, `version`, `version_commit`/`src_dir`/`install_ports` (for the update), `openmenu_games.json` (the openMenu link's game list), `players_sources.json`, `players_cache.json` (the last online list), `admin_pin` (PIN hash), `allowed_hosts`, `update_origin`, `https.crt`/`https.key`. The base's are in `base_core.py`, each module's in its own files.
- `/tmp/dreampi-netswitch.*`: `active`, `state`, `modem`, `port` (written by the hook), `net` (web service -> LED), `wifi` (Wi-Fi setup -> web/LED), `wbtest`, `update`/`update.log`, `updateinfo` (last manual update check -> LED), `reboot` (reboot marker -> LED); `/tmp/dreampi-netswitch-dtmf.log` is the debug timeline.
- Details of each: see the docs below.

## Testing without a Pi
`sh tests/run.sh` runs the off-hardware tests (`tests/`: buttons debounce/hold, Wi-Fi setup helpers, LED pipeline and render, web config + HTTP round trips on a random port with all paths redirected into a temp dir, page JS syntax and id references, hook Python 2 syntax guard, layering, shell syntax, the module system with every module removed / switched off alone and all gone). `tests/support.py` has `sandbox()` for redirecting paths. The routing test that needs the real `netlink.py` is described in `docs/hook.md` and is not in the suite. To look at the page run `python3 tests/ui/demo_server.py` (the real web service on a sandbox; env switches `WIFIDEMO=1 FAKEUPDATE=1 FAKEPLAYERS=1 BG=1 OFF=led,wifi|all LEDS=n PORT=n`, see its docstring) and screenshot it with Playwright (Chromium is pre-installed; scripts need `NODE_PATH=/opt/node22/lib/node_modules`). The clock and events modules are off in the demo server unless `CLOCK=1` / `EVENTS=1` (`EVENTSOON=1`: a reminded event 5 minutes ahead; the events module always reads its sample there, `DC99_MOCK=1`). `sh tests/ui/run.sh` is an optional UI audit at four screen widths (overflow, clipped text, tap targets, unlabelled controls, duplicate ids, stretched pills, JS errors, failed requests) plus `tests/ui/functional.js`, which drives the real page (network switching, colours, numbers table, LED colour rows / priority / palette editor, forms, module picker, debug log); run it after changing `page/` or a layout. When editing `page/page.css` add rules with an exact-string anchor, never by 'first occurrence of a selector' (that once split a rule in half).
